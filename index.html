환율 바 읽는 법

각 화면 상단의 💱 2026-08-15 ER-API · $1 = ₩1,415 … 가 오늘 환율입니다. 하루 한 번 자동으로 가져오고, 모든 사람이 같은 값을 씁니다.

조회 실패 시 — 수정 버튼을 눌러 직접 입력하세요. 저장하면 전 직원에게 같이 적용됩니다.
환차손익

평가 환차손익은 아직 안 판 재고의 장부상 이익입니다. 실현 환차손익은 출하할 때 확정되는 실제 손익입니다.

계산식 — 수량 × 외화단가 × (오늘환율 − 매입환율)
예) $320짜리 12M을 환율 1,400에 샀는데 오늘 1,415라면 → 12 × 320 × 15 = +57,600원

4 입고 메뉴 › 입고

물건이 실제 도착했을 때 등록합니다. 등록 즉시 재고에 반영됩니다.

01

소재 입고

  • 신규 자재 — 처음 들어오는 합금·형상·규격·Heat No.
  • 기존 자재 추가입고 — 같은 Heat No.에 수량을 더할 때
  • 공급처 · 입고일 · P/O · 인보이스 번호 · MTC 확보 여부를 함께 기록합니다.
  • 통화 · 매입단가 · 매입환율을 반드시 입력하세요. 이게 원가의 기준입니다.
추가입고 시 원가 — 같은 통화면 수량 가중평균으로 자동 재계산됩니다.
예) $120@1,300으로 50M 보유 + $150@1,400으로 50M 입고 → $135@1,350
02

베어링 · 기타 입고

소재와 폼 구성은 같고, Heat No. 대신 품명 · 분류 · 규격 · 안전재고 · 위치를 씁니다. 신규 품목은 자동으로 품목 마스터가 생성됩니다.

03

부대비용 정산 — 실제 마진을 알려면 필수

운임·관세 인보이스는 물건보다 늦게 옵니다. 도착하면 입고 이력에서 해당 건의 💰 부대비용 정산을 누르세요.

  • 운임·보험 / 관세·부가세 / 통관·하역 / 기타를 실제 금액으로 입력합니다.
  • 물품대 + 부대비용 = Landed Cost, 나누기 수량 = 실제 단가
  • 저장하면 재고에 실제 단가가 저장되고, 수주 화면의 원가계산이 추정치 대신 이 값을 자동으로 씁니다.
정산하지 않으면 — 수주 화면은 부대비용을 10% 추정으로만 계산합니다. 실제가 15%였다면 그만큼 마진을 착각한 채 팔게 됩니다.

5 ＋ 재고 실사 조정 — 장부와 실물이 다를 때

재고조사에서 수량이 안 맞으면 입고·출하로 억지로 맞추지 마세요. 실사 조정으로 처리해야 원인이 기록에 남습니다.

01

어디서 하나

소재 — 재고 상세(행을 탭)에서 📋 실사 조정 버튼
베어링·기타 — 품목을 펼치면 📋 실사 버튼

02

실측 수량과 사유를 입력

실제 세어본 수량을 넣으면 장부와의 차이가 자동 계산됩니다. 사유는 6가지 중 선택합니다.

  • 실사 차이 — 원인 불명의 수량 차이
  • 파손·불량 — 사용 불가 판정분 차감
  • 분실 — 소재 위치 확인 불가
  • 오입력 정정 — 입고·출하 때 숫자를 잘못 넣은 경우
  • 샘플 제공 — 고객사 테스트용 무상 제공분
  • 기타 — 비고에 상세 기재
03

확정하면 이력이 영구히 남습니다

장부 수량이 실측값으로 바뀌고, 조정 전/후 수량 · 차이 · 사유 · 조정자 · 일시가 삭제되지 않는 이력으로 기록됩니다. 월말 보고서에 그 달의 조정 내역 전체가 표로 들어갑니다.

하지 말 것 — 차이를 없애려고 가짜 입고나 출하를 등록하면 매입·매출 숫자까지 오염됩니다. 반드시 실사 조정으로 처리하세요. 조정은 로그인한 본인 이름으로 기록됩니다.
6 수주 메뉴 › 수주
01

가용재고 확인 — 중복 판매 방지

품목을 고르면 이렇게 표시됩니다.

현재고 12M − 수주 8M = 가용 4M
[출하준비] 부산플랜트텍 3M 2026-08-18
[수주] 대한중공업 5M 2026-08-21

이미 다른 곳에 팔기로 한 수량을 뺀 진짜 팔 수 있는 수량입니다. 초과 입력하면 빨간 경고가 뜹니다.

02

판매단가 정하기

부대비용률과 목표 마진율을 넣으면 권장 판매단가가 계산됩니다.

매입단가 (매입환율 기준) ₩452,800
＋ 부대비용 10% → ₩498,080
권장 판매단가 (마진 20%) → ₩597,696 [적용]
  • 적용을 누르면 판매단가에 자동 입력됩니다.
  • 단가를 직접 넣으면 실마진율이 역산됩니다 — 목표 이상 초록 / 미달 주황 / 역마진 빨강
  • 부대비용을 정산한 품목은 추정률 대신 실제 정산값이 자동으로 쓰입니다.
  • 맨 아래 오늘환율 재조달원가는 참고용입니다. 이 값이 매입원가보다 크면 다음에 살 때는 더 비싸다는 뜻입니다.
03

고객 P/O 번호

고객사가 준 발주번호입니다. 출하 라벨에 함께 찍히고, 고객사 입고 담당자가 대조하는 데 씁니다.

04

수주 이력

정렬은 최근순 / 납기순 / 거래처순. 행을 펼치면 상세 · 수정 · 삭제가 나옵니다.

수정에서는 거래처 · 수량 · 단가 · 납기 · 진행 상태 · 고객 P/O를 바꿀 수 있습니다.

01

단계 진행

수주 → 출하지시 → 출하준비까지는 상태만 바뀝니다. 재고는 줄지 않습니다.

02

출하 등록 — 부분 출하 지원

🚚 출하 등록을 누르고 이번에 나가는 수량을 입력합니다. 수주 10M 중 4M만 먼저 보내도 됩니다.

  • 미리보기에 출하 후 잔여 수주 · 출하 후 재고 · 출하 금액 · 환차손익이 나옵니다.
  • 잔여 수주나 현재고를 초과하면 처리되지 않습니다.
  • 부분 출하면 상태는 출하준비로 남고, 누적이 수주량에 도달하면 자동으로 출하완료가 됩니다.
  • 출하 1건마다 재고 차감과 환차손익이 확정되어 따로 기록됩니다.
03

배송비 입력 — 부담 주체가 핵심

출하 등록 창에서 배송비와 부담 주체를 입력합니다. 5만 / 10만 / 15만 빠른 버튼이 있습니다.

  • 당사 부담 — 우리 비용입니다. 미수금에는 안 들어가고, 미수금 화면 이달 배송비(당사)에 합산됩니다.
  • 고객 청구 — 물품금액에 배송비를 더한 청구 총액이 미수금(채권)으로 잡힙니다.
  • 착불 — 기사·화물에 고객이 직접 지불. 금액은 기록만 하고 정산에서 제외합니다.
구분을 틀리면 — 당사 부담을 고객 청구로 넣으면 받지도 못할 돈이 미수금에 잡혀 채권이 부풀고, 반대로 하면 청구할 돈을 안 받게 됩니다. 출하 시점에 운송 조건을 반드시 확인하세요.

출하 이력의 라벨 버튼으로 매수를 정해 인쇄합니다. A4에 3열로 배치됩니다.

소재 — LOT = Heat No., QR을 찍으면 해당 자재가 바로 열립니다. MTC 첨부 여부가 배지로 찍힙니다.
베어링·기타 — LOT = 출하번호(SO)
공통 — 품명 · 규격 · 수량 · 거래처 · 고객 P/O · 출하일
왜 Heat No.를 찍나 — 고객사가 재질 이의를 제기하거나 SQ 심사를 받을 때 추적 근거가 되는 건 Heat No.뿐입니다. 고객 P/O는 대조용 보조 정보입니다.

① 들어올 때 — 수입 부대비용 (Landed Cost)
01

입고 시점엔 물품대만 확정됩니다

운임·관세 인보이스는 물건보다 며칠~몇 주 늦게 옵니다. 그래서 입고 등록 때는 부대비용을 입력하지 않고, 시스템은 임시로 추정률 10%를 얹어 계산합니다.

02

인보이스 도착 → 부대비용 정산

입고 › 입고 이력에서 해당 건의 💰 부대비용 정산을 누르고 4가지를 실제 금액으로 입력합니다.

  • 운임·보험 — 해상/항공 운임, 적하보험
  • 관세·부가세 — 수입신고 시 납부액
  • 통관·하역 — 관세사 수수료, THC, 창고료, 상하차
  • 기타 — 검사비, 국내 운송(항구→창고) 등

비고에 포워더·인보이스 번호를 남겨두면 나중에 대조가 쉽습니다.

03

저장하면 재고 단가가 진짜 원가로 바뀝니다

물품대 ＋ 부대비용 ＝ Landed Cost ÷ 수량 ＝ 실제 단가

이후 수주 견적 화면은 추정 10% 대신 이 실제 단가로 권장 판매가와 마진을 계산합니다. 미정산 건은 입고 이력에 부대비용 미정산으로 표시됩니다.

정산을 안 하면 — 실제 부대비용이 15%였는데 10%로 견적하면, 그 차이 5%p만큼 마진을 착각한 채 파는 겁니다. 니켈합금은 단가가 커서 한 건에 수십만 원씩 새어 나갑니다.
② 나갈 때 — 국내 배송비
01

출하 등록 창에서 바로 입력

용차비·화물비를 배송비 칸에 넣고 부담 주체를 고릅니다. 별도 화면이 아니라 출하 처리와 한 번에 끝납니다.

02

부담 주체에 따라 돈의 방향이 다릅니다

  • 당사 부담 → 비용. 미수금에 안 잡히고 이달 배송비(당사) KPI로만 집계
  • 고객 청구 → 매출 가산. 물품금액＋배송비＝청구금액으로 미수금에 잡힘
  • 착불 → 고객이 기사에게 직접 지불. 기록만 남기고 정산 제외

거래명세서·세금계산서 발행 시 물품가액과 운반비를 나눠야 하므로 시스템은 물품금액(amount_goods)과 배송비를 따로 저장합니다.

③ 한눈 요약 — 비용이 흘러가는 길
발주 → 물품대 확정(매입환율 고정) → 입고 → 인보이스 도착 → 부대비용 정산 → 실제 단가 확정 → 수주 견적(실제 단가 기준 마진 계산) → 출하 → 배송비 입력(부담 주체) → 수금(청구금액 기준)
월말 점검 두 가지 — ① 입고 이력에서 부대비용 미정산 건이 남아 있지 않은지 ② 미수금 화면의 이달 배송비(당사)가 예상 범위인지. 이 두 숫자만 챙겨도 마진 착시가 사라집니다.
